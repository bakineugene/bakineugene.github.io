Я наконец-то закончил с hello world мигалками на всем подряд. Перехожу к изучению прерываний.

Для начала прерывания на AVR, как более простой вариант. Тем более мне же нужно кнопку к тиньке подключить для управления режимами, а вставлять обработку в основной цикл - как-то уже слишком по-детски.

В целом прерывание это способ повесить обработчик на событие. Механизм отличается, но суть остается.

Конкретно для AVR в качестве сигнала для процессора, что пора обрабатывать событие, служат определенные биты в регистрах. Их выставляет периферия или сам процессор в определенных случаях. Затем, на границе инструкций, процессор осуществляет проверку выставленных флагов событий. Если какой-то из флагов выставлен И обработка прерываний включена (за это отвечает Bit 7 – I: Global Interrupt Enable в SREG – Status Register) - то процессор выбирает один из них (с наименьшим адресом "вектора прерывания") и исполняет.

Вообще, как только начинаешь читать про прерывания - тебе сразу начинают вещать про эти вектора прерываний. По сути вектор прерываний "ведет" к обработчику прерывания. Поэтому, видимо, "вектор". Для stm32, вроде бы, это буквально адрес по которому лежит обработчик, для AVR это JMP/RJMP инструкция с переходом на этот адрес. 

```
The vector is normally a jump to the interrupt routine, and this jump takes three clock cycles.
```

1. Происходит некое событие
2. Информация об этом событии пишется во флаг прерывания
3. Процессор узнает об этом
4. Смотрит нужно ли обрабатывать это событие (глобально SREG + специфичные биты для каждого конкретного прерывания) 
5. Находит в векторе прерывания информацию о том как обработать данное событие
6. Переходит в обработчик
7. После обработки возвращается к выполнению кода

Разрешить и запретить обработку прерываний можно используя макросы sei() и cli(). Кроме того, можно ручками сбрасывать любые флаги событий.
По умолчанию, после того как началась обработка прерывания, процессор сам вызывает cli() и прерывание внутри прерывания вызвано не будет. НО, во-первых, можно самостоятельно разрешить данное поведение, вызвав sei(). Во вторых, биты отвечающие за данное событие все равно будут проставлены и (после завершения обработки текущего прерывания и выполнения одной инструкции из main) процессор снова запустит обработку следующего. 

Вот список доступных векторов прерываний для attiny13a:

```
Address Labels Code Comments
0x0000 rjmp RESET ; Reset Handler
0x0001 rjmp EXT_INT0 ; INT0 Handler
0x0002 rjmp PCINT0 ; PCINT0 Handler
0x0003 rjmp TIM0_OVF ; Timer0 Overflow Handler
0x0004 rjmp EE_RDY ; EEPROM Ready Handler
0x0005 rjmp ANA_COMP ; Analog Comparator Handler
0x0006 rjmp TIM0_COMPA ; Timer0 CompareA Handler
0x0007 rjmp TIM0_COMPB ; Timer0 CompareB Handler
0x0008 rjmp WATCHDOG ; Watchdog Interrupt Handler
0x0009 rjmp ADC ; ADC Conversion Handler
```

Из интересного сейчас:
INT0 - доступен только на PB1 (6 ноге). Позволяет "подписываться" на передний и задний фронт сигнала.
PCINT0 - доступен для всех GPIO ног. Для каких конкретно будет срабатывать - можно выбрать по маске (PCMSK). Фронт выбрать нельзя и узнать точно на какой именно ноге сработало - тоже нельзя (но можно хранить предыдущие значения и сравнивать).
WATCHDOG - это такой низкоточный таймер, работающий от отдельного встроенного осциллятора. Собираюсь его использовать для debounce.

1. PCINT0

```c
#define PCINT0_CLEANUP() GIFR |= (1 << PCIF)
#define PCINT0_ENABLE() GIMSK |= (1 << PCIE)
#define PCINT0_DISABLE() GIMSK &= ~(1 << PCIE)
#define PCINT0_ENABLE_PIN(pin) PCMSK |= (1 << pin)
```

Для включения используется регистр GIMSK (General Interrupt Mask Register) Bit 5 – PCIE: Pin Change Interrupt Enable
Для выбора пинов, активирующих прерывание, используется регистр PCMSK (Pin Change Mask Register). Номер бита соответствует номеру пина.
Событие, ожидающее обработки, сохраняется в регистр GIFR (General Interrupt Flag Register) Bit 5 – PCIF: Pin Change Interrupt Flag

2. WATCHDOG

Судя по описанию - это специальный таймер, который следит за тем, что МК не завис и обрабатывает прерывания. Т.е. если WATCHDOG активирован в определенном режиме - то при отсутствии реакции на прерывание со стороны МК - будет принудительно вызван RESET. Однако это поведение можно не активировать и использовать WATCHDOG как обычный таймер. 

```c
#define WDT_PREPARE_CHANGE() WDTCR = (1 << WDCE)
#define WDT_DISABLE() WDTCR = 0x0
#define WDT_ENABLE_INTERRUPT_250() WDTCR = (1 << WDTIE) | (1 << WDP2)
```

WATCHDOG управляется через регистр WDTCR – Watchdog Timer Control Register.
Чтобы полностью отключить watchdog - достаточно обнулить регистр
Чтобы изменить настройки watchdog - нужно сделать пару приседаний:

```
Bit 4 – WDCE: Watchdog Change Enable
This bit is used in timed sequences for changing WDE and prescaler bits. To clear the WDE bit,
and/or change the prescaler bits, WDCE must be set.
Once written to one, hardware will clear WDCE after four clock cycles.
```

Сначала устанавливаем специальный бит WDCE, а потом сразу же (в течении четырех тактов) производим необходимые настройки.
Настройка частоты срабатывания устанаваливается с помощью четырех бит WDP[0-3] позволяющих выставить "делитель" для счетчика таймера. Максимальное значение таймера ~ 8 секунд. Поделив на 32 получим примерно 250 мс.

Поведение управляется двумя битами:
Bit 6 – WDTIE: Watchdog Timer Interrupt Enable
Bit 3 – WDE: Watchdog System Reset Enable

WDE включает RESET если МК не смог обработать прерывание
WDTIE просто позволяет реагировать на прерывание

```c
ISR(PCINT0_vect) {
    PCINT0_DISABLE();

    PORTB_TOGGLE(PB4);

    cli();
    WDT_PREPARE_CHANGE();
    WDT_ENABLE_INTERRUPT_250();
    sei();
}

ISR(WDT_vect) {
    WDT_DISABLE();
    PCINT0_CLEANUP();
    PCINT0_ENABLE();
}
```

В обработчике "кнопки" переключаем светодиод, выключаем обработчик "кнопки" и включаем таймер.
Больше на кнопку не реагируем пока обратно не включим обработчик по завершению таймера.
