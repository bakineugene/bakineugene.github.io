Пора уже елку убирать, а я еще не доделал некоторых вещей для гирлянды, которыми хотел заняться на праздниках. 
В качестве компромисса решил, что перед уборкой сделаю еще запись текущих настроек в память.

`EEPROM - Electrically Erasable Programmable Read Only Memory`

Т.е. память, которую можно только читать, но еще и стирать и писать. 🤪

Согласно объяснению от Ben Eater ([https://www.youtube.com/watch?v=BA12Z7gQ4P0](https://www.youtube.com/watch?v=BA12Z7gQ4P0)):
`ROM` - сначала делали просто память только для чтения, которая содержала данные с завода.
`PROM` - затем стали производить память, которую можно было записать лишь однократно специальным программатором.
`EPROM` - затем стали делать память, которую после программирования можно стереть ультрафиолетом.
`EEPROM` - можно стереть специальным программатором, или вообще in-curcuit.

Вот так и пришли к памяти только для чтения, в которую можно писать.

Тем не менее эта память все равно позиционируется как "в основном для чтения" ([https://www.youtube.com/watch?v=7qa1dsCpMMo](https://www.youtube.com/watch?v=7qa1dsCpMMo)). 

Используется для хранения конфигурации и пользовательских настроек.

У `EEPROM` есть ограничение на число "стираний". У `attiny13a` в даташите указано "минимум 100_000 циклов". 
Поэтому рекомендуется применять `wear leveling` методики работы с этой памятью. 
Стараться равномерно изнашивать всю память, а не писать все время в одну область. 

**Разница с FlashROM**

У stm32, например, нет встроенного `EEPROM`, вместо этого есть возможность выделить под конфигурацию место в флеш памяти.

Насколько я понял, flash память построена на тех же принципах, что и `EEPROM`, но "удешевлена". 
Если для `EEPROM` есть доступ до каждого байта, то `Flash` орудует "страницами" от 1Kb.
Соответственно для записи 1 байта конфигурации нужно перезаписать целую "страницу".
К тому же и erase циклов на порядок меньше - около 10_000.
Но зато и память дешевле.

Контроллеры для flash-карточек и SSD применяют хитрые `wear leveling` алгоритмы чтобы изнашивать память равномерно. Там это еще актуальнее.
Скажем, для управления 512 Gb SSD диском от samsung применяется 5 ядерный S4LR020, с 512 Мб оперативной памяти, 4 ядра которого заняты исключительно работой с flash ячейками.
Небольшой компьютер из начала нулевых только чтобы диском управлять.

**5.3 EEPROM Data Memory**

attiny13a имеет "на борту"
64 байта EEPROM с побайтным доступом
100000 write/erase циклов для каждого байта

Для полного цикла write/erase требуется аж 3.4 ms. 
Отдельно на чтение и запись - по 1.8 ms (Можно выполнить erase, "подготовив" память для записи заранее, а можно выполнять erase/write одной командой)

**5.3.6 Preventing EEPROM Corruption**

Для успешной записи в EEPROM необходимо стабильное питание.
Чтобы предотвратить запись при недостаточном напряжении питания - рекомендуется использовать EEPROM в комбинации с Brown-out Detector (BOD).

```
ATtiny13A has an On-chip Brown-out Detection (BOD) circuit for monitoring the VCC level during
operation by comparing it to a fixed trigger level.
```
